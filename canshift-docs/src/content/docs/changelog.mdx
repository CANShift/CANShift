## Release-notes convention

Every release should follow this structure:

```markdown
## [Version] — YYYY-MM-DD

### 🚗 For the driver
- (UX, new widgets, hardware support, etc.)

### 🔧 For the tuner / installer
- (config, calibration, ECU parameters)

### 🔬 Firmware / dev
- (build flags, schema, Rust ports, refactors)

### ⚠️ Breaking
- (concrete impact + required action — re-flash, re-burn config, etc.)

### PRs
- #XXXX — ...
- #YYYY — ...
```

An empty release, or one reduced to a bare list of PR titles, is not enough:
the public changelog must be readable by someone who didn't watch the
development stream.
