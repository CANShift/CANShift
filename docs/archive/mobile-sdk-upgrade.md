# Mobile SDK upgrade plan — Expo 52 → 53

Tracking issue: [#390](https://github.com/tburkhalterr/CANShift/issues/390).
Status: planning only. **Do not start the upgrade until this plan is approved
and the prerequisite audit issues are closed.**

## 1. Current state

`canshift-mobile` ships on Expo SDK 52 with React Native 0.76.9, React 18.3.1,
NativeWind 4.1.23, Hermes, and a portrait-only iOS-first build. Key runtime
deps: `expo-file-system@~18.0.12`, `expo-secure-store@~14.0.1`,
`expo-font` (via Expo modules), `expo-status-bar@~2.0.0`,
`react-native-ble-plx@^3.5.1`, `react-native-reanimated@~3.16.1`,
`react-native-safe-area-context@4.12.0`, `react-native-screens@~4.4.0`,
`react-native-svg@15.8.0`. Two custom config plugins are registered in
`app.json`: `withGlogFmtFix` (latest version merged in PR #554 — patches
**both** the `pbxproj` target build settings and the per-pod `xcconfig` for
`fmt`/`glog`, because patching the xcconfig alone is overridden by the
project-level setting) and `withSilencePodsWarnings`. The native `ios/` and
`android/` directories are regenerated by `expo prebuild` and are gitignored —
all persistent native config lives in `app.json` and the two plugins.

## 2. Target state

Expo SDK 53 ships React Native 0.79 and React 19. Exact versions of pinned
sub-deps (Reanimated, expo-file-system, expo-secure-store, …) must be
re-verified against the official Expo SDK 53 release notes at upgrade time;
this plan locks in the high-level path, not the patch numbers. Two hard
requirements come with SDK 53:

- **Node ≥ 20 in CI.** The GitHub Actions mobile workflow must be confirmed at
  Node 20 LTS before the umbrella PR opens.
- **React Native New Architecture (Fabric + TurboModules) is enabled by
  default.** This is the single biggest behavior risk — see §3 and §6.

## 3. Breaking changes affecting our deps (audit)

### React 19 path

- **What changes.** RN 0.79 ships React 19. Stricter `act()` semantics,
  `useId` / `use()` available, removed legacy lifecycle warnings, ref-as-prop
  changes, and tightened concurrent rendering behavior.
- **Our exposure.** `react-hook-form@^7.75.0`, `zustand@^5`,
  `@hookform/resolvers@^5`, `class-variance-authority`, `tailwind-merge`,
  `react-native-toast-message`, `@react-navigation/*@^7`. All current versions
  advertise React 18 peer deps; some already declare React 19 support but
  must be re-checked at upgrade time.
- **Mitigation.** Run `npx expo install --fix` plus `npx expo-doctor` after
  the bump. If any dep still pins React 18 peer-wise, add a
  `package.json` `overrides` block (carefully — the existing `preinstall`
  guard already blocks two known-bad overrides for `tar` and `@xmldom/xmldom`).
  Verify React Hook Form behavior on the BLE settings forms (largest form
  surface in the app).

### Reanimated 4 + Worklets v2

- **What changes.** Reanimated 4 splits worklets into a separate
  `react-native-worklets` package and changes the Babel plugin path. v4
  requires the New Architecture.
- **Our exposure.** We currently rely on Reanimated 3 transitively through
  React Navigation and NativeWind. We have no first-party Reanimated 4-only
  feature need in the next 6 months.
- **Mitigation.** Per sub-issue [#437](https://github.com/tburkhalterr/CANShift/issues/437),
  pin `react-native-reanimated@3.17.4` (the version Expo SDK 53 expects) for
  the umbrella PR. Re-verify the pin against SDK 53's `expo install --fix`
  output at upgrade time. Defer the Reanimated 4 migration to a follow-up
  driven by NativeWind v5 adoption (see below).

### NativeWind v4 vs v5

- **What changes.** `nativewind@4.2.0` is broken on SDK 53 (missing
  `react-native-worklets/plugin`). The two viable paths:
  - **Pin to v4.1.x** — minimal diff today, but blocks Reanimated 4 and is at
    real risk of dead-ending on SDK 54.
  - **Migrate to v5** — recommended for SDK 53+, larger diff (babel preset,
    metro plugin, `className` typing changes), but forward-compatible.
- **Recommendation.** Migrate to **v5** in a dedicated sub-PR landed
  *before* the umbrella runtime bump. Rationale: we already use `cva` +
  `tailwind-merge` patterns that v5 handles cleanly, the migration cost is
  one-time, and pinning to v4 only delays the same migration by one cycle
  while building up incompatible Reanimated 3 baggage. Final call is recorded
  in sub-issue [#438](https://github.com/tburkhalterr/CANShift/issues/438).

### `expo-file-system`

- **What changes.** SDK 53 requires `expo-file-system@>=18`. We are already
  on 18.0.12, but we previously hit an OTA hashing breakage on the 17 → 18
  jump that pinned us to 17.0.1 for a window (see #386 and #401 for the
  postmortem).
- **Mitigation.** Re-run the OTA full-flow regression test (factory bin →
  device → reboot) end-to-end on real hardware *before* shipping. The
  previous bug was a silent hash mismatch, not a build error — only a real
  flash catches it.

### `expo-secure-store`, `expo-font`, `expo-network`

- **What changes.** All three get major version bumps with SDK 53. Likely
  surface: `expo-secure-store` API shape for biometric-gated reads;
  `expo-font` async loading defaults; `expo-network` connectivity event
  payload.
- **Our exposure.** SecureStore is used for the BLE pairing token and any
  remembered device list. `expo-font` loads the dashboard typography on app
  boot. `expo-network` is used only for the OTA WiFi detection path.
- **Mitigation.** Audit each call site after `expo install --fix`. If any
  breaking API surface is touched, capture the diff in the umbrella PR
  description; do not silently adapt without a note.

### `withGlogFmtFix` config plugin

- **What changes.** The plugin (latest form in PR #554) patches both the
  `pbxproj` target build settings *and* the per-pod `xcconfig` files to
  force `gnu++17` on `fmt`/`glog`, working around the Xcode 16 + Clang 18 +
  RN 0.76 `__cpp_consteval` regression. **Patching only the xcconfig is
  insufficient** — the project-level setting overrides it. This learning
  must survive into SDK 53.
- **Our exposure.** Whether RN 0.79 still bundles a `fmt` version that
  triggers the bug is **TBD** until we run a clean prebuild against the SDK
  53 template. Likely still needed if RN 0.79 ships fmt 11.x.
- **Mitigation.** Per sub-issue [#439](https://github.com/tburkhalterr/CANShift/issues/439):
  on the first clean SDK 53 prebuild, run an iOS build with the plugin
  enabled and one with it disabled. Three outcomes:
  - Both succeed → remove the plugin, close #382 as superseded.
  - Plugin still needed and the regex anchor still matches → leave a
    comment in the file noting it's still required on SDK 53.
  - Plugin still needed but the regex anchor breaks (likely if SDK 53 ships
    a Swift AppDelegate with a different Podfile shape) → update the anchor
    *and* add a snapshot test of the patched Podfile.

### `react-native-ble-plx`

- **What changes.** `react-native-ble-plx@3.5.1` is current. The official
  compat table only goes up to RN 0.74; RN 0.79 + NA is uncharted.
- **Our exposure.** BLE is the entire reason the mobile app exists.
  Connection drops, scan failures, or MTU regressions are merge-blockers.
- **Mitigation.** Per sub-issue [#440](https://github.com/tburkhalterr/CANShift/issues/440),
  a **real-hardware spike is mandatory** before the SDK 53 umbrella PR can
  merge. Test scan, connect, MTU negotiate, characteristic
  read/write/notify, reconnect after firmware reset, and Bluetooth-toggle
  mid-session — twice (NA on and NA off) on a real iPhone. Decision matrix:
  works on NA → ship NA on. Breaks on NA, works on legacy → ship NA off and
  file a follow-up. Breaks on both → fall back to a maintained fork or
  block the upgrade.

## 4. Test surface to re-validate post-upgrade

Manual end-to-end pass on a real iPhone (and at least one real Android
device for parity checks):

- BLE scan → connect → MTU negotiate → notify on the **TELE** characteristic.
- BLE reconnect after firmware reset (forced power cycle).
- BLE behavior when Bluetooth is toggled off mid-session and back on.
- WiFi OTA full flow (factory bin pushed to device → device reboot →
  version string updates).
- Biometric auth backed by SecureStore (face unlock for pairing token).
- Safe area / notch handling on iPhone 17 Pro (Dynamic Island top inset,
  home indicator bottom inset).
- Navigation stack transitions (push, pop, modal present, deep link entry).

All seven must pass before the umbrella PR is merged. A failure on any one
either gates the merge or downgrades a default (e.g. NA off per §3).

## 5. Upgrade sequence

Staged, not big-bang. Big-bang fails review and rolls back painfully.

1. **Foundation.** Close the open mobile audit items — #385, #386, #388 —
   so SDK 53 starts from a clean baseline. Confirm CI Node version is ≥ 20
   on the mobile workflow.
2. **Hardware spike — mandatory gate.** Execute sub-issue
   [#440](https://github.com/tburkhalterr/CANShift/issues/440) on real
   hardware. Record the NA-on vs NA-off result in the issue. No SDK 53
   merge happens until this spike is complete and documented.
3. **Decision PRs.** Lock in three decisions, each captured in its own
   sub-issue body before the umbrella PR opens:
   - [#438](https://github.com/tburkhalterr/CANShift/issues/438) — NativeWind v4 pin vs v5 migration.
   - [#441](https://github.com/tburkhalterr/CANShift/issues/441) — New Architecture default.
   - [#439](https://github.com/tburkhalterr/CANShift/issues/439) — `withGlogFmtFix` re-evaluation.
4. **Umbrella PR.** Sub-issue
   [#436](https://github.com/tburkhalterr/CANShift/issues/436). One large
   PR per Expo's official upgrade guidance — but only after steps 1–3 are
   green. The PR runs `npx expo install --fix`, applies sub-issue #437
   module alignment, records the NA decision in `app.json` explicitly (no
   implicit default), and ships with the green test surface from §4.

## 6. Effort + risk

- Hardware spike: 1–2 days.
- NA decision (sub-issue #441 documentation pass): 0.5 day.
- NativeWind v5 migration (assuming that is the chosen path): 1–2 days.
- Umbrella PR + module alignment + test surface pass: 1–2 days.
- **Total: roughly one sprint of mobile-only effort**, gated by real
  hardware availability for the spike.

**Single biggest risk: the React Native New Architecture.** Fabric +
TurboModules change measurement, gesture, BLE bridging, and Reanimated
runtime behavior. If `react-native-ble-plx@3.5.x` regresses under NA, the
release ships with NA explicitly opted out (`"newArchEnabled": false` in
`app.json`) and a follow-up issue is filed to re-enable NA before SDK 54
removes the opt-out — this is the default recommendation in
[#441](https://github.com/tburkhalterr/CANShift/issues/441) regardless of
the spike outcome, traded against a smaller blast radius for the first SDK
53 release.
