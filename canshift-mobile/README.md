# CANShift Mobile

<p align="center">

iPhone companion app for the CANShift dashboard. Active development, iOS-first, Android secondary.

Stack: Expo SDK 52 (bare workflow via prebuild), React Native 0.76, TypeScript, Zustand, react-native-ble-plx 3.5.

---

## Quickstart

```bash
cd canshift-mobile
npm install
npx expo prebuild --clean   # regenerates ios/ and android/ from app.json
npm run ios                  # build and launch on simulator/device
```

The `ios/` and `android/` folders are gitignored — they are regenerated by `expo prebuild` from `app.json` and the `plugins/` config. All persistent native config lives in `app.json`.

Other scripts: `npm run lint`, `npm run typecheck`, `npm run android`.

## BLE protocol

The mobile app talks to the firmware-side GATT server in [`canshift-firmware/src/hal/ble/ble_server.cpp`](../canshift-firmware/src/hal/ble/ble_server.cpp). UUIDs and the compact telemetry key map are mirrored in `src/constants/ble.ts` — keep both sides in sync when characteristics change.

Characteristics:

- `BLE_CHAR_TELE` — telemetry notifications (compact JSON, keys defined in firmware `addSignalIfValid()`)
- `BLE_CHAR_STATUS` — device status
- `BLE_CHAR_SETTINGS` — read/write settings
- `BLE_CHAR_CMD` — command channel

OTA uses Wi-Fi, not BLE. The dashboard exposes itself as `192.168.4.1` (AP mode); the phone joins that network and posts the firmware binary via `ota.service`.

## iOS notes

`app.json > expo.ios.infoPlist` declares:

- `NSBluetoothAlwaysUsageDescription` / `NSBluetoothPeripheralUsageDescription` — required for BLE scan/connect.
- `NSLocalNetworkUsageDescription` — required for OTA over the dashboard's AP.
- `NSAppTransportSecurity > NSExceptionDomains > 192.168.4.1` — allows plaintext HTTP to the dashboard during OTA. The ESP32 has no TLS cert; this exception is intentional and scoped to that single host.

Bundle identifier: `ch.tmbk.canshift`. iPad is disabled (`supportsTablet: false`).

## Reuse from canshift-core

Shared types and validators are consumed from `canshift-core` when needed (same package the desktop studio uses). The dependency is added on demand — currently the mobile surface only needs the BLE telemetry shape, which is owned locally in `src/constants/ble.ts`.
